*clarify.txt*  AI explanations beside your code

Requires Neovim 0.11+ and curl. See README.md for installation and provider setup.

Web search is DISABLED BY DEFAULT. See |clarify-web-search| to opt in.

COMMANDS                                              *:AIClarify*
:[range]AIClarify [topic]
    Explain the cursor word or topic using nearby code and optional LSP hover.
    With a selection/range, explain the selected code as a whole. An optional
    topic focuses the explanation. Brief explanation, 1-2 examples.
    Does not edit source buffers or override your LSP mappings.

:[range]AIExplain [topic]                              *:AIExplain*
    Detailed explanation of the same feature, with 3-4 examples, mechanisms,
    use cases and pitfalls. Supports the same topic and range as AIClarify.
    Visual selections preserve character, line, and block boundaries. Select
    code, then type :AIExplain (or :AIClarify); Vim supplies the visual range.
    Selections are capped at 80 lines and 12,000 bytes, marked as truncated.
    A selected keyword/symbol uses the feature explanation style. Expressions,
    functions, classes and larger selections get a walkthrough of the whole code.

:AIClarifyCancel                                      *:AIClarifyCancel*
    Cancel the pending explanation. A new request or closing the pane cancels it.

PANE                                                  *clarify-pane*
    Opens beside your cursor like LSP hover, with an animated loading spinner.
    Uses Neovim's LSP popup positioning to fit above/below and avoid screen edges.
    Moving the source cursor or typing closes the float and cancels its request.
    Cursor movement inside the explanation window keeps it open for reading.
    Set window = 'split' for the right/bottom-right pane layout.
    Focus stays in your code. Use CTRL-W w to enter. q or Escape closes the window;
    gx opens a documentation URL. gs opens Google's Search Suggestions widget
    in your browser when provided by a grounded Gemini answer.
    Noice's spinner highlight is used when available; no dependency is required.

WEB SEARCH                                            *clarify-web-search*
    DISABLED BY DEFAULT for both AIClarify and AIExplain.
    Set web_search = true in setup() to opt in for both commands.
    Without search, documentation links are model suggestions, not verified
    sources. Compatible endpoints do not support web search.

CONFIGURATION                                         *clarify-setup*
>lua
    require('clarify').setup({
      provider = 'gemini', -- openai, anthropic, compatible
      web_search = false, -- disabled by default; true opts in
      window = 'float', -- or 'split'
      -- gemini_api_key = 'your-key',
      -- model = 'gemini-3.5-flash-lite',
      -- api_key = function() return your_secret_store_lookup() end,
      timeout_ms = 30000,
      lsp_timeout_ms = 200,
    })
<
    No default mappings. setup() is optional with Gemini and GEMINI_API_KEY.
    Default models: gemini = gemini-3.5-flash-lite, openai = gpt-4.1-mini,
    anthropic = claude-haiku-5-5. Set model to override the selected provider's
    default; omit it to keep the default. Use a model supporting that provider's
    API (Gemini generateContent, OpenAI Responses, Anthropic Messages) and,
    when enabled, its web search tool.
    compatible requires model and base_url (API root including /v1 as needed).
    base_url also overrides hosted API roots. HTTPS is required except for
    local HTTP on localhost or 127.0.0.1.
    Direct key fields: gemini_api_key, openai_api_key, anthropic_api_key,
    compatible_api_key. Only the selected provider's key is used.
    Precedence: api_key > <provider>_api_key > standard environment variable.
    Standard variables: GOOGLE_API_KEY or GEMINI_API_KEY for Gemini,
    OPENAI_API_KEY for OpenAI/compatible, ANTHROPIC_API_KEY for Anthropic.
    GOOGLE_API_KEY wins over GEMINI_API_KEY if both are set. No custom env names
    or automatic .env loading are supported.
    Keys accept strings or functions; a nil function result falls back to env.
    Keep literal keys in a private configuration file outside version control.

LOCAL OLLAMA                                          *clarify-ollama*
    Start Ollama (ollama serve) and pull a local model (ollama pull llama3.2).
    Use its OpenAI-compatible API:
>lua
    require('clarify').setup({
      provider = 'compatible',
      base_url = 'http://localhost:11434/v1',
      model = 'llama3.2', -- exact name from ollama list
      api_key = '', -- no key needed; skip OPENAI_API_KEY
      web_search = false,
      timeout_ms = 120000,
    })
<
    Both commands use this model. The plugin does not start Ollama or download
    models. With a downloaded local model, context stays on your Ollama server.
    Web search is unavailable; documentation links are unverified suggestions.
    API details: https://docs.ollama.com/api/openai-compatibility

PRIVACY                                               *clarify-privacy*
    Sends up to 12 surrounding lines on each side, or 80 range lines, capped at
    12,000 code bytes; up to 8,000 LSP hover bytes; target, filetype and position.
    Runs only on explicit command. Provider data policies and API charges apply.
    Model explanations and links can be incorrect; inspect the cited evidence.
